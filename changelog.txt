EMI Paged Bookmarks 更新日志

1.0.24 - 2026-09-10
-------------------
代码清理：把 IDEA 报的错误与警告逐个过了一遍，**行为零变化**。
- `mods.toml`：依赖表的键写死成 `[[dependencies.emipagedbookmarks]]` —— `${mod_id}` 这种未加引号的
  占位符只在打包时被替换，源码里是非法 TOML，IDEA 会报「应为 <key segment>」（打包后的文件本来
  就正确，改完源码也不再报）。
- `mods.toml`：`accessTransformers = []` 挪到 `[[mods]]` 之前 —— Forge 是从根层读这个键的
  （`ModFile.getConfigElement("accessTransformers")`），原先写在 `[[mods]]` 之后会被 TOML 归到
  模组条目里、等于没写。
- `mods.toml`：`clientSideOnly=true` **保留**。IDEA 报「ClientSideOnly is only available since 49.0.6」
  是插件版本数据过期：47.4.20 的 `ModFileInfo` 确实读这个键并置 `__FORGE_clientSideOnly`
  属性（已反编译确认），专用服务端仍会跳过本模组。
- Mixin：`ScreenSpaceMixin` 的排布缓存字段挪进嵌套类 `LayoutCache`；`EmiFavoritesMixin` 的常量与
  快照状态补 `@Unique`、两个快照辅助方法加 `emipagedbookmarks$` 前缀。Mixin 会把这些「新增成员」
  灌注进目标类，所以它们必须带 `@Unique` 且名字含 `_`/`$`，否则可能与 EMI 自己的成员撞名
  （IDEA 的 Mixin 检查也会一直报）。
- 顺手清理：冗余空赋值（两处 UUID 解析、一处反序列化，抽成小工具方法）、`File.mkdirs()` 返回值被
  忽略（改用会抛异常的 `Files.createDirectories`）、手工解码改 `Files.readString`、
  `BookmarkPages.removeCurrentPage()` 去掉没人用的 boolean 返回值、
  `GroupInteraction` 里可简化的 if、`GroupManager.extractFromGroup` 与 `moveItem` 重复的实现、
  三个 Screen 覆写 `render` 缺 `@Nonnull`、`fillPadding` 永远返回 0（并入 `IntList.padRowTo`）、
  `GroupOverlay` 里 4 处「参数恒定」的私有方法（贴图 id、clamp 范围、顶点格式、框选色），
  以及 `NOISE_LATTICE` 的 Javadoc 里指向自身的那条 `{@link}`（改成 `{@code}`）。
- `GroupOverlay` 里 `new ResourceLocation(命名空间, 路径)`：IDEA 报「自 1.20.6 起已弃用并标记为移除」
  是**误报**（1.20.1 的类文件里没有该注解，已用 javap 确认；`fromNamespaceAndPath` 要 1.20.6 才有），
  只在那一处加了 `@SuppressWarnings({"deprecation", "removal"})` 并写明原因。

1.0.23 - 2026-09-10
-------------------
边框带收窄：2px 实心 + 向内 2px 延伸（原来向内 4px，整体 6px -> 4px）。
- `ditherLayers` 4 -> 2（`solidRows` 本来就是 2）。带宽从 6px 收到 **4px**，最多只往图标方向
  探 2 个像素。
- 延伸层仍然"从实心带连出来生长"（8 连通，不会有孤点）、仍然带低频噪声让深浅有起伏，
  也仍然**从背景直接取样**（是花就是花）。
- 实测一条 64 格长的边：厚度分布 2px 22.4% / 3px 26.0% / 4px 51.7%，平均 **3.29px**
  （改之前 6px 带宽平均约 4.8px）。
- 顶点规模随之腰斩：满页 1136 quad / 4544 顶点 / 160KB -> **706 quad / 2824 顶点 / 99KB** 每帧，
  仍是**恒定 2 次 draw call**。
- **修了一个「改了默认形状却没效果」的坑**：`bookmarks.json` 里的 `"border"` 每次存档都会被写回，
  于是旧版本写下的值一直被读回来、把新的代码默认值永久盖住。现在给这个对象加了 `"v"` 版本号，
  版本对不上（含没有 `v` 的旧文件）就整段忽略、退回代码默认值。
  **以后改动 `solidRows`/`ditherLayers`/`ditherStart`/`ditherDecay` 的默认值，记得把
  `BORDER_CONFIG_VERSION` +1**，否则老配置文件里的旧值会继续生效。
  首次运行时若看到日志「边框形状配置版本 v0 != v1，忽略旧值」，属正常。

1.0.22 - 2026-09-10
-------------------
花型改用指定像素定义；边框带成为「背景的一扇窗」—— 向内延伸的像素也直接取背景（是花就是花）。
- **花型全部替换**（3x3 十字 / 3x3 四角 / 5x5 菱形 / 6x6 胖菱形 / 7x7 大花），只有三种颜色：
  亮黄 #FDDA4A、暗黄 #E7C01E、白 #FFF3F1；没有描边也没有绿叶。每个黄色像素各自独立随机取亮/暗，
  中心固定白（"中间接近白色，四周黄色可深可浅"）。6x6 是中列+中行各复制一份、白心变 2x2 的"变胖"版；
  7x7 大花是"中间-四周但不把四周填满"，占比很少。
- **3x3 的花瓣会掉落**：每片花瓣 28% 概率掉落，偶尔只剩中间一个白点
  （实测 0瓣 12.6% / 1瓣 5.6% / 2瓣 21.5% / 3瓣 36.6% / 4瓣 23.8%）。
- **覆盖率 40%**，花层像素级互不重叠（撞上就整朵换位置重试）。
- **边框不再区分"实心带 / 散点带"**：两趟绘制（草地 + 花）遍历**同一批矩形、同一个顺序**，
  每个像素都按绝对坐标从背景贴图取样 —— 那一格背景是花就是花、是地就是地。
  所以**向内延伸出的像素现在也会带花**，和它旁边的背景永远对得上。
- 随之删掉了矩形里的 `kind` 字段（实心/散点的区分已经没有意义），绘制收敛成两个同构的 pass。
- 顶点规模翻倍（满页 1136 quad / 4544 顶点 / 约 160KB 每帧），仍然是**恒定 2 次 draw call**。

1.0.21 - 2026-09-10
-------------------
花型改为「参考包 flower hotbar」那种四周包裹的竖长花苞，覆盖率降到 40%。
- **花型整体重做**：原先的花是"开口星形"（顶端 `y y` 分叉、横向花瓣伸出），被 2px 边框横切
  之后会露出 `Y..Y..Y` 这样的孤立碎瓣，很突兀。新花型参考参考包 flower hotbar 的黄色郁金香：
  **最外一圈是连续闭合的深绿描边**、绿色叶托从两侧与下方包住黄白色花瓣。被直边裁断时，切口是
  一条干净的连续色块（`GGGGG` / `GYYYG` / `GYWYG`），这才是边框带该有的样子。
- **四档尺寸全部闭合**：大 7x11 / 中 5x8 / 小 5x5 / 点 3x3（每行实心像素必须连续，生成器里
  有断言自检）。配色照抄参考包：亮黄 #FDDA4A、中黄 #E7C01E、白 #FFF3F1、
  亮绿 #61B620、中绿 #438A0C、深绿 #26450F。
- **覆盖率 60% -> 40%**：可直接看实心带上"有多少像素是花"（实测约 48%），想再调就改生成器的
  `FLOWER_COVERAGE` 后重跑。
- **碎点大幅减少**：花型铺设权重实测挑选 —— 3x3 的小点从 2353 个降到 291 个（原本占全部花的 41%，
  一片噪点），现在主体是大/中/小花（360 / 1521 / 2029）。
- **加了个文本自检**：`gen_bg_field.py --art` 会把每个花型打成字符画并断言"每行实心像素连续"，
  这样不用开游戏（也不用看图）就能核对轮廓是否闭合。`preview_field.py` 也加了 `band_text()`，
  把边框带直接打成字符图看最终观感。
- 只改贴图，Java 侧与几何算法未动。

1.0.20 - 2026-09-10
-------------------
边框收窄、向内延伸改为「连通生长」，草地与花层重做。
- **边框 4px 实心 -> 2px 实心**，向内延伸仍是 4 层（总带宽 8px -> 6px），不再往格子里探太深。
- **散点必须连回边框**：以前每一层各自掷骰子，会出现孤零零的一个像素点。现在改成
  「从实心带出发、只保留能沿已有点像素 8 连通地连回边框的候选」—— 即印刷里的 clustered-dot
  聚集点思路：点只成簇长大、不会散开。同层之间也允许横向连着长，所以边缘是不规则的团块。
- **延伸有厚有薄**：每层阈值再乘一个 16px 尺度的低频噪声，有的地方伸到 4 层、有的地方只伸 1~2 层，
  不再是"一圈等厚的毛边"。
- **草地重做，增加深浅层次**：噪声尺度从 16~64px 扩到 8~128px（新增 128px 的大块明暗），
  并按直方图把范围拉满（原先只有 30% 的明暗差，实测一片平）。可见外圈的明暗对比度从 7% 提到 17.5%。
- **花层**：巨花数量大幅减少（约占花型总数的 1%，原先铺满时几乎连成一片）；花之间**不再重叠**
  （像素级互斥，放不下就换位置），并按铺设进度自动从大花切换到中小花填缝。覆盖率仍为 60%。

1.0.19 - 2026-09-10
-------------------
边框改为「从整页草地贴图按绝对坐标取样」，删掉上一版那套按分组合成边框环的复杂机制。
- **一整页草地**：新增两张可无缝平铺的 512x512 贴图 —— 灰阶草地（按分组颜色染色）与彩色花层
  （黄白花，不被染色，花约占画面 60%，大小与位置随机散布）。边框直接从贴图上按**格子的绝对像素
  坐标**取样，于是同一个位置永远取到同一个像素：上下、左右相邻的分组在交界处取到的是同一批纹理，
  **草自然连成一片**，不需要任何"检测相邻边"的特殊处理。
- **边框向内延伸的像素点**：外侧 4px 实心，再往内 4 层按概率保留、每层概率乘 0.75（即每层降 25%），
  散点像素同样取自草地贴图的对应位置。这些随机点**只在分组创建时算一次**并记在配置里（每个分组一个
  随机种子），绘制时只是查表，不产生每帧开销。
- **形状可配置**：实心厚度、向内层数、起始概率、每层衰减系数四项保存在 bookmarks.json 的 "border" 里。
- **大幅简化**：删掉按分组各自合成边框环的整套代码（相位、共用边检测、分段循环、角块让位、双层对齐、
  四边四角取样方向规则）与旧的 140x280 环图集；整页仍然恒定 2 次绘制调用（草地一趟 + 花一趟），
  与分组数量无关。轮廓描边与换行（分组跨行时整圈闭合）机制保持不变。

1.0.18 - 2026-09-10
-------------------
相邻分组共用边时融合成一整块草地，并减少"不成形的花瓣"。
- **共用边融合**：上下相邻（共用横边）或左右相邻（共用竖边）的两个分组，原先各画一道
  最外圈的亮框线，交叠成一条很明显的"双缝"，看着像被割裂。现在检测到共用边后，把那条边
  最外 1px 的框线换成草叶，两组边框合成一条 2 倍厚（12px）的连续草地，中间没有分隔线，
  于是可以跨组放一整片花。
- **相位改用绝对像素坐标**：纹样的取样偏移不再按分组各自算，而是由格子所在的绝对坐标决定，
  这样两个相邻分组在共享边界上采到的是同一批纹理像素，草纹自然连成一片、看不出接缝。
- **减少"不成形的花瓣"**：巨花贴边那一行原先占满 11 像素，被裁到只剩 1px 高时就是一条
  没有形状的黄色横条；现在把巨花/大花在中轴线上的可见宽度收窄（11→7、7→5），并且把巨花的
  出现频率从 0.7 降到 0.3，大花/中花也从 0.75 降到 0.55；微花散点密度与白心点缀同步下调，
  d=0 上最长空档上限放宽到 20px。整体绿色更连贯、黄色更像一朵朵花。
- 共用边检测按行分桶 + 链表，复杂度 O(行数)，所有中间缓冲复用，渲染热路径零分配；
  整页仍然恒定 2 次绘制调用，与分组数量无关。

  花的最外一行特意钉在格子的最外 1px 上，保证永远露出的那一圈能看到花瓣。
- 藤叶改为不规则散布，去掉可辨认的重复单元。

1.0.12 - 2026-09-10
-------------------
性能：把「每帧重建收藏栏排布」改成「变更时才重建」。GPU 占用原本随收藏数量线性上涨，
本条针对其中属于本模组的那部分开销（EMI 的逐物品直绘与 GTO 的数量文本渲染不受此影响）。

- 新增全局布局版本号（`LayoutVersion`）：任何改动分页、收藏顺序、分组归属或折叠状态的操作
  统一让所有布局缓存失效。失效点收敛到 `BookmarkPages.save()`，不容易漏。
- `ScreenSpace.getStacks()` 的注入结果按「分页 + 布局版本 + 每行列数 + 临时收藏条数」缓存。
  EMI 每帧会从多处调用它（hover 判定、翻页、滚动、渲染主循环），原先是每次调用都对全部收藏
  重建一遍列表；现在稳定状态下是零分配的直接返回。
- `GroupManager` 的折叠映射改为按版本预构建的映射表：`hidden()` 不再每次新建 HashSet，
  `toFoldedIndex` / `toOriginalIndex` 由「重建集合 + 线性扫描」改为查表 O(1)。
  它们在边框绘制里每个分组、每帧都会被调用多次。
- `BookmarkPages.visibleFavorites()` 增加缓存：不再每帧对全部收藏重建 HashMap、
  也不再每帧为每条收藏生成一次键值字符串。
- `GroupOverlay` 的分组取色由 O(n²) 改为一次预计算；换行填充的 `ArrayList<Integer>`
  改为 int 数组，去掉逐项装箱。

等价性：新旧两套索引算法已用离线对拍脚本验证（103,098 次索引比较，
`toFoldedIndex` / `toOriginalIndex` / 整页排布三项全部零差异）。

1.0.11 - 2026-09-10
-------------------
- 分组边框改为画在物品图标「下层」：18px 的格子里图标是 16x16、画在 +1 处，边框压在下层后
