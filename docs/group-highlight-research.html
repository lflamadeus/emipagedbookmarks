01结论先行

「独占行」的问题不是不够好看，而是它买错了东西

「分组感」在视觉设计里是最便宜的一类信息——留白、底色、一条边线，任何一种都比整行空白便宜。 而独占行用一整行（9 列就是 9 个格位）去买它，还在每个分组前后各买一次。下面是三组真实算术：

网格宽度分组情况不分组独占行（现状）行内 1 格间隔分组轮廓
9 列4 组 × 5 项（20 项） 3 行 · 浪费 7 格 4 行 · 浪费 16 格（44%） 3 行 · 浪费 4 格 3 行 · 0 额外格
5 列4 组 × 3 项（12 项） 3 行 · 浪费 3 格 4 行 · 浪费 8 格（40%） 3 行 · 浪费 0 格 3 行 · 0 额外格
9 列6 组 × 4 项（24 项） 3 行 · 浪费 3 格 6 行 · 浪费 30 格（56%） 4 行 · 浪费 11 格 3 行 · 0 额外格

注：EMI 侧栏每行可用格数并不固定（ScreenSpace.widths 会被排除区截断，甚至出现 0 宽行）， 所以真实浪费只会比上表更多。分组越小、行越窄，独占行的浪费越夸张——而书签分组恰恰以小组为主。

推荐落地顺序

  1. 先删掉独占行，布局回归 1:1 映射。你已经有一套 GroupOverlay 在画分组边框了，独占行是在为同一件事付第二遍钱。
  2. 首选替代：分组轮廓（common region）。零新增渲染路径——把每组的可见区间交给现有 GroupOverlay 即可，空间成本 0 格。
  3. 次选：行首强调色条。跨行分组天然连续，不需要算包围盒，是 12 个方案里实现成本最低的一个。
  4. 加分项：悬停聚焦。鼠标停在某一项时，同组提亮、他组压暗（Path of Exile 的 Highlight Items 就是这一套），零空间成本、辨识度极高。
  5. 你已经有的折叠格，做成数量徽章，比空行省得多，且 JEI 生态里已有成熟参照。

02为什么这些做法有效：四条设计依据

下面 12 个方案不是随便凑的，它们分别对应四条被反复验证的视觉原则。理解这四条，就能自己判断某个花哨效果值不值得加。

邻近原则 · Proximity

靠得近的元素被感知为同组。用留白「连接」或「分开」是最便宜的方案，且不需要新增任何视觉对象。

对独占行的直接含义：你花掉的整行空白确实是「分开」，但代价是唯一一种需要牺牲容量的手段。

Nielsen Norman Group · Proximity Principle in Visual Design

共同区域 · Common Region

边界之内的元素被感知为同组，而且共同区域能压过邻近原则——即使格子挨得很紧，一圈轮廓也能干净地切出分组。

这就是「分组轮廓 / 底色块」类方案的理论依据，也是本报告的首选推荐。

Nielsen Norman Group · The Principle of Common Region

边界不可滥用 · Overuse = Clutter

NNG 同时警告：边框与色块纯粹为装饰而加就会变成噪音；整宽的边界还会造成「假地板」，让人误以为内容到底了。

独占行正是「假地板」的极端形式：一条通栏空白，看起来就像这一页结束了。

同上（Caution: Overuse Creates Clutter）

颜色不能是唯一手段 · WCAG 1.4.1

用颜色传达信息时，必须同时提供形状、位置或文字等非颜色线索；仅靠色相区分对色觉障碍用户不可用。

所以「每组一个颜色」必须配上边框形状、角标或分组标题，才是站得住的方案。

W3C · Understanding SC 1.4.1

A · 空间类

用格位本身说话：留白、间隔、分隔线

现状：独占行（每组前后各留一整行）

独占行（换行分组）不建议保留

做法：分组开始前把当前行补满，分组结束后再补满一次，于是每组独占若干整行。

为什么被反对：它同时踩中两条设计原则的红线——用最贵的资源（容量）买最便宜的信息（分组感），并且制造通栏空白即「假地板」，视觉上像内容到此为止。

唯一合理的残留形式：把它降级成组前 1 格间隔（见下一项），而不是一整行。

强，但方向是「割裂」而非「归组」
实现成本
你现有的 FavoriteLayout 已实现

行内 1 格间隔（只在组间插一个空格）

行内间隔（gutter gap）性价比最高

做法：组与组之间只插入 1 个空位，不换行。跨行时分组自然接续。

证据：这就是设计文章里说的「用留白连接或分开」，也符合 NNG 的「优先用留白，不够再上边界」。 Tubik 的分隔符指南把 spacing 列为最不需要新对象、最经得起响应式变化的一种分隔。

代价：插入 1 格会推挤后面所有项，需要布局层支持「非 1:1 的可见索引映射」——也就是你现在这套 outputToVisible / visibleToOutput 映射，可以原样复用，只是把 PADDING 的粒度从「整行」改成「1 格」。

实现成本

分隔线 + 分组标题（subheader）

建材
食物

分隔线 + 分组标题信息量最高

做法：插入一个矮行，左端是分组名，右侧渐隐细线。这是唯一顺带把「这组是什么」讲出来的方案，其余 11 种都只能表达「这是一组」。

证据：Tubik 把「分隔符 + 子标题」单列为一类，理由是它降低认知负荷——用户不必自己推断结构。 NNG 的共同区域文章也把「tab/accordion 标签与内容同框」列为同类手法。

代价：占位约半行高（比整行便宜一半以上），且需要分组有名字。你的 FavoriteGroup 目前只有 lineBreak 这类布尔状态，要落地得先加一个可选 name 字段。

视觉强度
中高，且可扫描性最好
实现成本
中：需要数据模型加字段 + 侧栏行高不统一

纯邻近：只调整间距，不加任何装饰

纯邻近（留白分组，零装饰）最保守

做法：只在组间留白，不加边框、不加底色、不加颜色。

证据：NNG 明确写过：能用留白讲清楚的分组就不该再加边框——他们举了 Backcountry.com 的例子，去掉边框后分组依然清晰，反而省下视觉处理开销。 在 EMI 这种本来就密集、底色还有纹理的侧栏里，这一条尤其成立。

代价：EMI 侧栏格子是紧贴排列的，2 格以上的留白会显著推挤内容；而且没有颜色或形状兜底，色觉障碍用户完全靠位置判断，属于 WCAG 1.4.1 的边界情况。

空间成本
每组 1~2 格
视觉强度
弱
实现成本
最低
风险
与「用户只是随手放了两个空位」难以区分

B · 区域类

用边界或底色把一组圈起来：共同区域的直接应用

分组轮廓：沿实际占位画一圈（含不规则边缘）

分组轮廓 / 分组框本报告首选

做法：沿分组实际占据的格子外缘画一圈边线。占位不规则时就是阶梯形轮廓，不需要补成矩形。

证据：JEI 非官方分支明确写着「展开的成员保持连续，并带 group border highlighting」，同时用蓝色括号标配方链、灰色括号标书签分组。 NNG 的 common region 指出边界能压过邻近原则——意味着格子可以挨得极紧，分组依然清晰，这正好解决 EMI 侧栏空间紧张的问题。

对你尤其划算：GroupOverlay 已经在做分组边框（草地 + 花 + 强调色 + 抖动边缘），轮廓只是把「边框覆盖哪些格子」的来源从独占行后的整齐矩形换成真实占位区间。

空间成本
0 格（只画在格子边缘）
视觉强度
强，且天然表达共同区域
实现成本
低：复用现有渲染器，只换输入
风险
相邻分组贴太近时两条边会挤在一起，需按现有做法合并外沿

角括号：只在包围盒四角画 L 形标记

角括号 / 括号分组（brackets）生态里最主流

做法：只在分组的左上、左下、右上、右下画短 L 形标记，中间不连线。

证据：这是 JEI 生态里最被认可的分组语言：JEI 非官方用蓝色括号表示配方链、灰色括号表示书签分组，还支持拖拽括号来合并成组。 在网格类游戏里，角括号也是选中/归组的通用语法（它同时表达「范围」和「可拖拽」）。

优点：比全轮廓更安静，视觉重量低，密集网格里不会糊成一片；对不规则占位只需要包围盒，实现比阶梯轮廓更简单。

空间成本
0 格
视觉强度
中，可同时存在多个分组而不吵
实现成本
低：包围盒 + 4 段线段
风险
包围盒会把组间的空格也框进来，需配合 1 格间隔使用

背景色块：每组一层低饱和底色

背景色块 / 斑马纹慎用

做法：同一分组的格子铺一层低饱和底色，组与组用不同色相或深浅交替。

证据：NNG 提到斑马纹是「把横向元素连起来」的常见手段；Slack 用整块底色把导航区从内容区切出来，也是同一原理。 网格游戏里最接近的成熟例子是 Highlighter（按附魔与类型给物品上不同颜色，19.8 万下载）——但注意它是给单个物品上色，不是给区域上色。

风险：EMI 侧栏本身有背景贴图与分组边框（草地/花），再叠一层色块会脏；而且底色是纯颜色线索，单独使用违反 WCAG 1.4.1。建议最多做「悬停时短暂出现」，不做常驻。

空间成本
0 格
视觉强度
强，但容易与既有底图打架
实现成本
低（逐格填色）
适配性

C · 色彩类

颜色编码：给格子或行首上色，成本极低但要配形状

每格彩色描边：按分组或稀有度给格子描边

每格彩色描边（slot border）下载量最高的一类

做法：给属于同一分组的格子各自加一圈同色描边，不画区域边界。

证据（这一类的顶流）： Item Borders —— 850 万下载 / 1.6 千关注，为物品格加彩色边框突出稀有度，还支持按物品 ID 或标签手动指定颜色； Highlighter —— 19.8 万下载，按附魔/类型上色；  r/feedthebeast 上按类别给物品上色的模组帖也属于同类。

要点：这些模组的成功恰恰说明玩家接受「颜色即分类」，但都停留在单格层面。你要表达的是「一组」而非「一类」，所以描边最好只用于组内一致性，边界仍交给轮廓或角括号，这样也满足 WCAG 1.4.1 的非颜色线索要求。

空间成本
0 格
视觉强度
中；格子多时会显得花
实现成本
极低：逐格 1px 描边
风险
描边与 EMI 自带的槽位高亮/悬停框可能叠加

行首强调色条：每行分组起始处一根竖条

行首强调色条（left accent bar）实现成本最低

做法：在每一行里「该分组第一个格子」的左侧画一根 2~3px 竖条，颜色按分组取。跨行时每行都有一根，视觉上自然读成同一组。

证据：这是编辑器与 IDE 里的老牌分组语法（折叠区、缩进导引线、diff 侧栏都用它），也是 Material 系「leading accent」的标准做法； 在网格游戏里，SlotGlow 这类高亮模组把它做成可配置的角标与描边（含脉冲、彩虹、透明度），说明玩家愿意为「一根条/一个角标」单独装一个模组。

为什么适合你：它不需要包围盒，也就不需要处理不规则占位、不需要判断相邻分组是否共边——只要知道「这一行的这个格是某组的第一个」，代码量是 B 族方案里最小的。

空间成本
0 格（画在格子内侧 2px）
视觉强度
中低，安静、密集网格友好
实现成本
最低：无需包围盒、无需共边判断
风险

D · 交互类

把分组信息放到「需要时才出现」，空间成本趋近于零

悬停聚焦（把鼠标移到网格上试试）

悬停聚焦 / 高亮 + 灰化辨识度最高

做法：鼠标停在任意一格时，同一分组的格子保持原样，其余全部压暗（或反过来：同组发光、其余不变）。

证据：Path of Exile 的仓库搜索「Highlight Items」是这一手法的教科书实现—— 官方 wiki 的描述是：匹配的物品加黄色边框，其余物品变灰，但仍可交互。 这条「变灰但不失能」的细节很关键，值得照抄。

为什么它是最优解之一：空间成本 0 格，不动布局、不动 FavoriteLayout 的任何映射逻辑，只在渲染层加一个「当前悬停项所属分组」的查询。 和你的 GroupOverlay 已有的悬停色（HOVER_TINT = 0xFFE34D）是同一条渲染路径，可以合起来做。

很强，且是瞬时的、不占常驻注意力
实现成本
低：一次 GroupManager.containing(pageId, index) 查询（你已有这个 API）

折叠为单格 + 数量徽章 + 双物品叠影

折叠为单格 + 数量徽章你已有基础

做法：整组折叠成一个格子，右下角挂一个数量徽章，格子里叠两层物品图标表示「这里面有多个」。

证据：JEI 非官方原文：折叠后的格子显示数量徽章与双物品叠影，折叠状态会被记住，Alt + 左键展开/收起，展开后成员保持连续并带分组边框。 另外两个高采用度的同类实现：Collapsible Groups (JEI/EMI) —— 100 万下载，把同类物品折进一个格子，可自定义名称/图标/颜色，支持标签与正则规则； Reliable EMI (REMI) 的 Stack Grouping 用 JSON 规则把同色羊毛之类折成一个可展开条目。

对你的意义：你的代码里已经有 folded() 概念和 toFoldedIndex 映射——把折叠格做成徽章，等于把「分组」这件事故意折叠起来，是比独占行省得多的空间策略，而且生态验证充分。

空间成本
负数：折叠后一组只占 1 格
视觉强度
强，且自带「可交互」暗示
实现成本

Collapsible Groups 100 万下载；REMI 作者累计 1540 万下载

蚂蚁线：虚线边框循环移动

蚂蚁线 / 跑马灯边框加分项，不宜常驻

做法：边框画成黑白（或双色）虚线段，并让虚线段沿边框循环移动。

证据：Wikipedia · Marching ants：这套效果由 MacPaint 的 Bill Atkinson 首创，Photoshop、GIMP 沿用至今， 作用是把选区边界与周围内容明确区分开——注意它的定位是「选中态」，不是「归属态」。

给你的建议：用它表达框选中的临时状态（你已有框选预览），不要用来表达「这是一个分组」。 另外你代码注释里已经记录过 1.20.1 的教训：GuiGraphics.blit 每次调用都是独立 draw call，逐块平铺能堆到几百次——常驻动画边框会持续吃这个成本。

0 格
视觉强度
很强（会抢注意力）
实现成本

风险

动效反馈：到达时闪白 / 脉冲

动效承担分组反馈值得借鉴的思路

做法：不靠静态装饰，而靠「移动 / 到达」的动画让用户看懂谁和谁是一组。

证据：Cogmind 作者 Kyzrati 在 《Iterative UI Design》里完整记录了这个迭代过程，最终形态是： 错峰滑动（每项在 0~700ms 内随机时刻起步，全部 300ms 到位）+ 到达时闪白再淡回原色（400ms）+ 到达音效。 他的结论是：闪白强化了「哪些东西刚移动过」，错峰让同时移动的物品可辨认。整个过程 4 小时做完，是「小成本高回报」的范例。

对你的意义：当用户新建分组或拖动分组时，让该组做一次短暂的脉冲/闪白，比常驻任何装饰都更省空间，且能直接复用你已有的顶点拼装渲染。注意同样要尊重「减少动态效果」设置。

强，但只在操作瞬间

06落到本项目：建议怎么做

第 1 步 · 让布局回归 1:1，把分组交给渲染层

现在的耦合点是：布局层为了画分组感而插入了 PADDING，于是 FavoriteLayout 必须维护一套「非 1:1 的可见索引映射」。 一旦分组不再占格，映射就退化成恒等映射，padToRowEnd、rowEnd、pageSize 三个私有方法以及随之而来的缓存键（cachedRowWidths）都可以一并去掉。 

// 现在：分组要占格，所以必须有映射
Result r = FavoriteLayout.build(rowWidths, itemCount, breakStart, breakEnd, breakCount);

// 建议：布局不再关心分组，分组只产出「每组的可见区间」交给 GroupOverlay
List<GroupSpan> spans = GroupSpans.of(pageId);   // 每组 [start, end) 的可见区间，按真实行宽回填
GroupOverlay.setSpans(spans);                        // 渲染层照旧画边框 / 色条

第 2 步 · 三选一（可叠加）的替代高亮

选项改哪里空间成本建议
A · 分组轮廓 把 GroupOverlay 的输入从「独占行后的整齐矩形」换成真实占位区间；不规则占位按阶梯轮廓画 0 格 首选，复用已有渲染器
B · 行首强调色条 布局输出「每行每组的首个可见索引」，渲染层画 2px 竖条（画在图标下层） 0 格 实现成本最低，可与 A 并存
C · 行内 1 格间隔 把 padToRowEnd 降级为「补 1 格」；映射逻辑保留但只在组边界插入一个 PADDING 每组 1 格 作为可选项，配合 A/B 使用

第 3 步 · 零空间成本的增强

  • 悬停聚焦：用你已有的 GroupManager.containing(pageId, index) 取当前悬停项所属分组，同组保持原色、其余压暗（建议 25%~35% 不透明度，且保持可交互——照抄 PoE 的做法）。
  • 折叠格徽章：你已有 folded() 与 toFoldedIndex，在折叠格右下角加数量徽章 + 双物品叠影即可，这是 JEI 生态验证过的语法。
  • 新建/移动分组时的一次性脉冲：借鉴 Cogmind 的「到达闪白」，比任何常驻装饰都省，注意尊重「减少动态效果」。

明确不建议

  • 整行留白（现状）：违反邻近/共同区域两条原则的取舍方向，且造成「假地板」。
  • 常驻背景色块：你已经有草地与花两层贴图，第三层底色会把物品图标压浑。
  • 常驻蚂蚁线：那是「选中态」语法，不是「归属态」语法；且 1.20.1 下逐块 blit 的 draw call 成本你已经在注释里踩过一次。
